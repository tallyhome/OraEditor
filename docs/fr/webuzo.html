Hébergement

Webuzo

Même geste que cPanel : envoyez le kit ready/ora-editor/ (déjà compilé) dans public_html. Rien à builder.

Déploiement

  1. End User Panel → File Manager → public_html.
  2. Uploadez le dossier ready/ora-editor/ tel quel.
  3. Ouvrez https://votre-site/ora-editor/editeur.html.
  4. PHP 8.1+ si vous utilisez l’upload / l’IA. Droits 755 sur uploads/ si besoin.

Application Node.js (Webuzo)

Si le panneau propose Node.js App :

  • Cela sert à faire tourner votre API (proxy IA, Update Manager), pas le Core dans Node.
  • Le navigateur charge toujours ora-editor.js en statique.
  • Vous pouvez y lancer le script exemples/update.mjs en cron.
N’essayez pas de « servir l’éditeur » uniquement via npm run dev en production. Vite est un outil de développement. En prod : fichiers buildés dans public_html.

WordPress / Laravel via Softaculous

  1. Installez WordPress ou Laravel avec Softaculous.
  2. Puis suivez WordPress ou Laravel.
  3. Les assets OraEditor vont dans le plugin WP ou dans public/vendor/ora-editor.

Cron Webuzo

End User → Cron Jobs. Exemples :

# Mise à jour manuelle assistée (si Node est installé)
0 4 * * * /usr/bin/node /home/USER/bin/ora-update.mjs >> /home/USER/logs/ora-update.log 2>&1

# Laravel
* * * * * /usr/bin/php /home/USER/public_html/artisan schedule:run >> /dev/null 2>&1
