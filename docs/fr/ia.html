Exploitation

Intelligence artificielle

L’IA transforme le Document Model (fragments de texte + chemins), jamais un blob HTML. Le navigateur n’a le droit de connaître qu’une URL de proxy. La clé reste sur le serveur.

Règle d’or. Ne mettez jamais sk-…, token Anthropic, ni secret Ollama dans ora-editor.js, dans un attribut HTML, ni dans un dépôt Git public. Une clé dans le client est considérée comme divulguée.

Où ça s’affiche

Preset full uniquement (ou features.ai: true). Un panneau Assistant IA apparaît sous la zone d’édition : Corriger, Reformuler, Traduire, Résumer, Développer, Simplifier, Générer. Un menu choisit le provider.

Il n’y a pas de dashboard IA séparé, pas de quota intégré, pas de facturation OraEditor.

Providers disponibles

ProviderÉtatComment l’activer
Mock Actif par défaut Aucune clé. Utile en démo / hors ligne. Renvoie les fragments (légère normalisation).
OraAI Grisé Réservé. Pas encore disponible. Ne pas documenter de clé « OraAI ».
OpenAI Via proxy aiProxyUrl: "/ora-editor/ai" + clé serveur. Inscrit automatiquement au boot.
API custom Via le même proxy Même URL, id custom. Votre backend route vers Claude, Mistral, Azure…
Ollama Local, à enregistrer Machine où tourne Ollama (souvent le poste dev, rarement le mutualisé).

Activer OpenAI / custom

const editor = new OraEditor({
  element: "#editor",
  toolbar: true,
  preset: "full",
  aiProxyUrl: "/ora-editor/ai", // votre route, same-origin
});

Dès que aiProxyUrl est défini, le Core enregistre les providers openai et custom. Les deux POST-ent le même corps JSON vers cette URL.

Requête (navigateur → votre proxy)

{
  "op": "correct",
  "scope": "selection",
  "fragments": [
    { "path": [0, 0], "text": "Bonjour   monde" }
  ],
  "language": "fr",
  "style": "neutre",
  "instruction": "optionnel"
}

op ∈ correct | rewrite | translate | summarize | expand | simplify | generate. scope ∈ selection | block | document.

Réponse (votre proxy → navigateur)

{
  "patches": [
    { "path": [0, 0], "text": "Bonjour monde" }
  ]
}
Si le JSON n’a pas un tableau patches, le Core lève « réponse invalide ». Ne renvoyez pas le payload brut ChatGPT (choices[0].message) sans le reformater.

Ollama (local)

Uniquement si le navigateur peut joindre Ollama (souvent http://127.0.0.1:11434 sur la machine de l’auteur). En production mutualisée, Ollama n’est en général pas installé.

import { createOllamaEngine, createLocalProvider } from "@ora-editor/core";

const engine = createOllamaEngine("http://127.0.0.1:11434", "llama3.2");
editor.ai.register(createLocalProvider(engine));

En script tag IIFE, ces helpers sont exportés avec le module ES ; le bundle navigateur Full enregistre le mock + le proxy. Pour Ollama en page statique, préférez un petit proxy PHP/Node qui parle à Ollama côté serveur (même contrat patches).

Sécurité du proxy

  • Authentification (session, Sanctum, nonce WP).
  • Throttle (ex. 20 req / 10 min / utilisateur).
  • Taille max des fragments (évite d’envoyer un roman à l’API).
  • Allowlist des op.
  • Logs sans y mettre la clé ni tout le document.

Prompt système suggéré

Tu reçois un JSON { op, scope, fragments: [{ path, text }] }.
Applique l'opération au texte de chaque fragment.
Réponds UNIQUEMENT par un JSON : { "patches": [{ "path": [...], "text": "..." }] }.
Conserve la langue source sauf si op = translate.
Ne rajoute pas de markdown.
