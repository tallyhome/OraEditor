Update Manager

L’Update Manager est un outil hôte : packages/update-manager, package npm @ora-editor/update-manager. Il n’y a pas d’écran dans l’éditeur, pas de dashboard, pas de bouton « Mettre à jour » livré.

Le navigateur ne peut pas écraser public/ora-editor/ora-editor.js. Toute mise à jour passe par SSH, cron, Artisan, CI, ou un upload FTP manuel.

Pipeline

  1. CHECK — télécharge le manifest distant (ora-editor.manifest.json).
  2. COMPAT — compare currentVersion et compatibleCore.
  3. BACKUP — copie le dossier assets actuel vers un dossier backup.
  4. DOWNLOAD — récupère l’archive (zip / tarball).
  5. VERIFY — SHA-256 de l’archive = checksumSha256 du manifest.
  6. INSTALL — extrait dans le dossier de destination.
  7. HEALTHCHECK — votre callback (fichier JS présent, taille > 0, etc.).
  8. SUCCESS — ou ROLLBACK (restaure le backup) en cas d’échec.

Manifest

Produit par npm run package dans dist/ora-editor/ora-editor.manifest.json :

{
  "name": "ora-editor",
  "version": "0.1.0",
  "channel": "stable",
  "compatibleCore": "^0.1.0",
  "files": ["ora-editor.js", "ora-editor.mjs", "ora-editor.css"],
  "checksums": {}
}

L’Update Manager attend aussi, pour une release distante :

{
  "version": "0.1.1",
  "channel": "stable",
  "changelog": "Correctifs couleur et colonnes",
  "checksumSha256": "…hash de l’archive…",
  "compatibleCore": "^0.1.0",
  "archiveUrl": "https://exemple.fr/releases/ora-editor-0.1.1.zip"
}

Canaux : stable, beta, nightly. Vous hébergez ces fichiers (GitHub Releases, votre CDN, un bucket). OraEditor ne fournit pas encore un dépôt public de releases.

Utilisation Node

import { createUpdateManager, createLocalFs } from "@ora-editor/update-manager";
import { readFile } from "node:fs/promises";

const mgr = createUpdateManager();
const release = await mgr.check("https://exemple.fr/ora-editor.manifest.json");

await mgr.apply(release, {
  destDir: "/var/www/site/public/ora-editor",
  backupDir: "/var/backups/ora-editor",
  currentVersion: "0.1.0",
  fetchArchive: (url) => fetch(url).then((r) => r.arrayBuffer()).then((b) => new Uint8Array(b)),
  extract: async (archive, dest) => { /* unzip vers dest */ },
  healthcheck: async () => {
    const js = await readFile("/var/www/site/public/ora-editor/ora-editor.js");
    return js.byteLength > 1000;
  },
  fs: createLocalFs(),
});

Brancher dans « votre » dashboard

Si vous avez un back-office (Laravel Nova, Filament, wp-admin, admin maison) :

  1. Bouton « Vérifier OraEditor » → appelle check(manifestUrl) en SSH/job, pas en Ajax public.
  2. Affiche version actuelle vs version distante + changelog.
  3. Bouton « Installer » → queue un job serveur apply(…).
  4. Journalisez les étapes renvoyées (check, backup, … success / rollback).
N’exposez pas apply sur une URL anonyme. Un attaquant écraserait vos JS. Réservez ça à un rôle admin + CSRF + confirmation.

Mise à jour manuelle (toujours valable)

  1. Sur le PC : npm run build && npm run package.
  2. Sauvegardez le dossier ora-editor actuel (zip).
  3. Uploadez les nouveaux .js / .css / manifest.
  4. Hard-refresh navigateur (Ctrl+F5) à cause du cache.
