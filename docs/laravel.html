Frameworks

Laravel

Le package ora/laravel vit dans packages/laravel du monorepo. Le Core TypeScript reste ignorant de Laravel : le package ne fait qu’embarquer les assets, une vue Blade, un upload et un proxy IA.

Installation du package

Depuis un projet Laravel 10+ (PHP 8.2+) :

# Chemin local tant que le package n’est pas sur Packagist
composer config repositories.ora-laravel path ../OraEditor/packages/laravel
composer require ora/laravel

php artisan vendor:publish --tag=ora-assets
php artisan vendor:publish --tag=ora-views

ora-assets copie packages/core/dist vers public/vendor/ora-editor. Pensez à npm run build dans OraEditor avant de publier.

Blade

<x-ora::editor
    :content="$doc"
    preset="full"
    id="ora-editor"
    upload-url="{{ url('/ora-editor/upload') }}"
    ai-proxy-url="{{ url('/ora-editor/ai') }}"
    wire-model="body"
/>
  • content : HTML ou JSON (string / document).
  • wire-model : optionnel, synchronise le JSON vers Livewire (wire:ignore autour de l’éditeur).
  • L’instance JS est exposée sur window.oraEditor (surchargeable via jsVar).

Routes à déclarer

Le ServiceProvider actuel publie vues et assets ; les routes restent de votre ressort (auth, throttle) :

use Ora\Laravel\Http\Controllers\UploadController;
use Ora\Laravel\Http\Controllers\AiProxyController;

Route::middleware(["auth", "throttle:30,1"])->group(function () {
    Route::post("/ora-editor/upload", UploadController::class);
    Route::post("/ora-editor/ai", AiProxyController::class);
});

L’upload enregistre dans le disque public, dossier ora-editor, et renvoie l’URL. Lancez php artisan storage:link.

Clé OpenAI

Dans .env (jamais commité, jamais envoyé au navigateur) :

OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini
OPENAI_URL=https://api.openai.com/v1/chat/completions

Dans config/services.php :

"openai" => [
    "key" => env("OPENAI_API_KEY"),
    "model" => env("OPENAI_MODEL", "gpt-4o-mini"),
    "url" => env("OPENAI_URL", "https://api.openai.com/v1/chat/completions"),
],

AiProxyController lit config("services.openai.key"). Sans clé : HTTP 503.

Le contrôleur transmet aujourd’hui le JSON brut d’OpenAI. En production, parsez le message du modèle et renvoyez strictement { "patches": [{ "path": [0, 0], "text": "…" }] } — c’est le contrat du Core. Détail : page IA.

Update Manager + Artisan

Créez une commande qui appelle le package Node @ora-editor/update-manager (via Symfony Process) ou portez le pipeline en PHP. Cron :

// app/Console/Kernel.php ou routes/console.php
Schedule::command("ora:update --channel=stable")->dailyAt("04:15");

Le navigateur ne doit pas pouvoir écrire public/vendor/ora-editor. Voir Update Manager.

cPanel / Webuzo + Laravel

  1. Document root du domaine = dossier public/ de Laravel (pas la racine du projet).
  2. composer install --no-dev --optimize-autoloader en SSH.
  3. php artisan vendor:publish --tag=ora-assets.
  4. .env avec APP_KEY, OPENAI_API_KEY, disque public lié.
